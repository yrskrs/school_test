# 📖 Інструкція користувача: SchoolTest (ШколярТест)

Ця інструкція допоможе вчителеві швидко опанувати систему **SchoolTest**, створювати та імпортувати тести, перевіряти помилки у реальному часі та ефективно проводити тестування у класі.

---

## Синхронізація й окремі учні у версії 1.6.4

1. Відкрийте «Списки → Синхронізація» та підтвердьте клас. Підбір учнів стане доступним одразу після цього.
2. Перегляньте пари «отриманий учень → місцевий учень». Система показує лише учнів відповідного класу; пошук звужує цей список.
3. Для точних однозначних ПІБ натисніть «Підтвердити точні збіги». Схожі імена й тезки перевірте окремо. Вибір «Локальні дані» збереже ваше написання, вибір «Отримані» застосує написання та активність із джерела.
4. Якщо це новий учень, виберіть «Створити нового учня» й отриману версію. Збережені ID й результати наявних учнів залишаються на місці.
5. Після підтвердження звичайні зміни передаватимуться автоматично. Якщо обидві сторони змінили запис, він знову з’явиться для перевірки. При повідомленні про зміну списку оновіть сторінку та повторіть перевірку.
6. У вкладці «Окремі учні» видно завершені спроби учнів поза списком та їх архів. Кнопки відкривають пояснений фільтр результатів; CSV відповідає обраній вкладці.

## 1. Графічна панель керування сервером (GUI) та Реєстрація

Для зручності запуск сервера та керування користувачами здійснюється через графічні вікна PyQt6 без необхідності роботи в консолі.

### 🔹 Запуск на Windows:
1. **Первинне налаштування**: запустити `setup_env.bat` для створення віртуального середовища.
2. **Запуск панелі**: відкрити `run_gui.bat` або `start_windows.bat`.
3. **Вікно реєстрації користувачів**: відкрити `start_register.bat` або натиснути кнопку **«👥 Користувачі / Реєстрація»** у головному вікні GUI Server Manager.

### 🔹 Запуск на Linux:
1. **Запуск панелі**: запустити `start_linux.sh` або `python3 run_gui.py`.
2. **Вікно реєстрації**: запустити `start_register.sh` або `python3 run_register.py`.

### 🌟 Основні можливості GUI:
- **Швидкий запуск/зупинка** сервера однією кнопкою.
- **Мережева адреса (IP та Порт)**: для швидкого копіювання адреси сервера та надання учням.
- **Моніторинг сесій**: перегляд підключених учнів, кольорові квадратики відповідей (зелені/червоні) у реальному часі.
- **Керування користувачами**: додавання акаунтів вчителів, зміна паролів, фільтрація та експорт списку в CSV.

## 2. Початок роботи в браузері та Зміна теми

### Вхід у систему та перший запуск:
- При першому запуску (якщо користувачів ще немає) система автоматично відкриє сторінку **`/setup`** для реєстрації головного адміністратора.
- Після створення облікового запису вхід здійснюється за вказаними вами логіном та паролем на сторінці `http://localhost:8000/teacher/login`.

### 🌙 Зміна теми оформлення (Light / Dark Mode):
- На **всіх сторінках вчителя та учня** (у вікнах входу, дашборді, редакторі питань, проведенні тесту та результатах) у правому верхньому кутку розміщено **стильну круглу плаваючу кнопку** зміни теми.
- Тема миттєво змінюється з плавним анімованим переходом та зберігається в пам'яті браузера.

## 3. Створення та Редагування тестів

1. Перейдіть у розділ **«Тести»** та натисніть **«Створити тест»**.
2. Вкажіть назву, предмет, клас, часовий ліміт та налаштування перемішування.
   Класи з профілю, локальних списків та власних імпортів API доступні в полі **«Клас»**. Щоб учні обирали себе зі списку, виберіть клас із учнями і збережіть тест. Якщо тест створено раніше без класу, задайте його в редакторі; клас не обирається окремо на сторінці входу учня.
3. У редакторі питань можна форматувати текст, додавати зображення, налаштовувати бали.
4. **Drag & Drop**: для питань на відповідність та послідовність підтримується перетягування варіантів відповідей мишкою.
5. **Скасування дій (`Ctrl+Z` / `Ctrl+Y`)**: при випадковому видаленні чи зміні варіанта можна легко відновити попередній стан.
6. **Індикатор завантаження (`TopLoader`)**: при збереженні тесту у верхній частині екрана відображається плавна смуга прогресу.
7. **Дублювання питань (`📋`)**: у шапці та у нижній частині картки кожного питання доступна кнопка **«📋 Дублювати питання»**. Вона створює точну копію питання разом із варіантами відповідей та позначеними правильними відповідями одразу під оригіналом для подальшого швидкого редагування.

У полі **«Дозволені проходження тесту»** виберіть **«Обмежена кількість»** і вкажіть число від 1 або виберіть **«Без обмежень»**. Число включає перше проходження: 1 забороняє повторні спроби, 3 дозволяє загалом три проходження. Ліміт діє для кожного учня в одній сесії; продовження незавершеної спроби й архівування результатів його не скидають. У новому тесті за замовчуванням дозволено одне проходження.

Прапорець **«Дозволити проходження поза списком класу»** вмикає для учнів пункт **«Мене немає у списку — введу ім’я самостійно»**. Без цього дозволу пункт прихований, а вхід поза наявним списком класу заблокований. Дозвіл за замовчуванням вимкнений; для тесту без списку учнів звичайне введення імені залишається доступним. Обидва налаштування зберігаються при експорті та імпорті JSON.

## 4. Інтелектуальна перевірка та Вікно аналізу помилок

Під час створення чи редагування тесту система в реальному часі аналізує правильність введених даних:

### ⚠️ Що фіксується як помилка:
- **Повторення варіантів відповідей у питанні**: наприклад, якщо у питанні №3 два варіанти мають однаковий текст (*«Так»* / *«Так»*).
- **Дублювання правих частин у відповідностях**: якщо у питанні на відповідність права частина повторюється.

> ℹ️ *Примітка*: Однаковий текст кількох питань (наприклад, *«Обчисліть:»* чи *«Установіть відповідність:»*) **не вважається помилкою** і не генерує хибних сповіщень.

### 🔍 Модальне вікно `🔍 Вікно помилок`:
- Натиснувши кнопку **«🔍 Вікно помилок»** у списку сповіщень, відкривається модальне вікно з пошуком і фільтрацією.
- **`🎯 Перейти до питання`**: сторінка плавно прокручується до питання та виділяє його імпульсним підсвічуванням.
- **`🗑️ Видалити це питання`**: видаляє проблемне питання з можливістю скасувати операцію через `Ctrl+Z`.
- **Жовті баннери**: безпосередньо у картці питання з'являється попереджувальний баннер із описом помилки.

## 5. Імпорт тестів з файлів (Word, MyTestX XML/MTF, JSON)

У розділі **«Тести» → «Імпортувати»** доступні чотири формати:

### 1. Імпорт із Word (`.docx`):
- Автоматично розпізнає номер питання (`1.` або `1)`), варіанти відповідей (`А)`, `Б)`).
- **Правильні відповіді** розпізнаються за зеленим кольором тексту, жирним шрифтом або позначкою `(+)`.
- Зображення, вставлені у документ Word, автоматично витягуються та зберігаються.

### 2. Імпорт із MyTestX (`.xml`):
- Сумісність із файлами XML, експортованими з програми MyTestX.
- Розпізнає назву тесту, розділи (`<Groups>`), питання (`<Tasks>`) та варіанти відповідей.

### 3. Прямий імпорт MyTestX (`.mtf`):

У розділі **«Тести» → «Імпортувати» → «MyTestX (.mtf)»** виберіть файл. На панелі вчителя також є кнопка **«Імпортувати MTF (MyTestX)»**. Сайт автоматично перетворить тест і відкриє його в редакторі; вручну запускати Mtf2Xml не потрібно.

Підтримуються тести MyTestX **10.2 без пароля**, розміром до **20 МБ**: одиночний і множинний вибір, послідовності, відповідності, введення тексту, точного числа та вибір області на зображенні. Кожна прийнятна коротка відповідь показується в редакторі з нового рядка. Теми, правильні відповіді, бали й растрові зображення переносяться автоматично.

Якщо зображення розміщені у правій колонці відповідностей, колонки міняються місцями зі збереженням правильних пар — сайт показує картинки в лівій колонці. Числові діапазони, спеціальні правила перевірки тексту, інші типи завдань і версії MTF можуть потребувати XML-експорту; сайт повідомить про непідтримувану структуру замість пропуску запитань.

Після імпорту перевірте налаштування тестування. Як і під час XML-імпорту, параметри часу та перемішування беруться з початкових налаштувань сайту; обмеження кількості запитань для окремих груп MyTestX автоматично не застосовуються. Імпортується весь банк запитань, навіть якщо в назві файлу зазначена кількість запитань для однієї спроби.

### 4. Імпорт із JSON:
- Швидкий формат для копіювання тестів між серверами SchoolTest.

## 6. Проведення тестування (Сесії та Моніторинг)

1. У списку **«Тести»** знайдіть потрібний тест за назвою, предметом або класом і натисніть **«Запустити»**. Час, перемішування, показ результатів, кількість проходжень і дозвіл на вхід поза списком класу задаються в редакторі тесту.
2. На сторінці моніторингу з’явиться **код доступу**. У списку **«Сесії»** кнопка **«Копіювати»** копіює посилання входу для учнів із цим кодом.
   Нова сесія зберігає вибраний список класу. Зміна класу в редакторі впливає на наступні сесії; чинна сесія з прив’язкою залишається зі своїм класом. Якщо потрібна інша сесія на сторінці учня, натисніть **«Ввести інший код тесту»**. Моніторинг повідомляє, коли список учнів не підключений або порожній.
3. Активні сесії показуються першими. Пошук і фільтри перевіряють увесь список, а не лише поточну сторінку.
4. У меню **«Керування»** можна поставити всіх учнів на паузу, продовжити проходження, закріпити сесію на сторінці входу або завершити спроби всіх учнів.
5. **«Закрити вхід до сесії»** забороняє нові входи та повторні спроби; учні, які вже проходять тест, можуть завершити свою спробу. Для дострокового завершення поточних спроб використовуйте **«Завершити всім учням»**. Це окремі дії.
6. **«Моніторинг»** відкриває прогрес, статуси, журнал і керування окремим учнем. Лічильник виходів із fullscreen/перемикань вікон відновлюється після оновлення сторінки.
7. Архів зберігає результати й прибирає записи з основного списку. Видалення тесту знищує також пов’язані сесії та результати — перед ним показується підтвердження.

## 7. Як учні проходять тест

1. Учень відкриває адресу сервера (наприклад, `http://192.168.1.100:8000` для локального запуску або порт `8080` у типовому Docker) та вводить код доступу чи обирає закріплений тест. За наявності списку класу вибирає своє ім’я; якщо це дозволено й імені немає, позначає «Мене немає у списку» та вводить його вручну. Без списку вводить ім’я одразу. **Клас задає вчитель у тесті.**
2. Після інструкції учень натискає **«Розпочати тестування»**, щоб увімкнути fullscreen. При виході показуються попередження й відлік часу; три порушення завершують тест. Звичайна вебсторінка не може заборонити Esc — для цього потрібен режим кіоску на керованому комп’ютері.
3. Вибрана або введена відповідь зберігається локально. Після **«Відповісти»** вона надсилається серверу; перехід до наступного питання відбувається після підтвердження.
4. При втраті зв’язку тест і браузерні таймери призупиняються. Чернетка, черга відповідей та події залишаються на пристрої; після відновлення зв’язку система повторює надсилання. Можна натиснути **«Перевірити зв’язок зараз»**.
5. **Залишайте вкладку відкритою.** Для продовження використовуйте той самий браузер, адресу сервера й пристрій зі збереженими cookie. ПІБ без cookie не дозволяє забрати вже розпочату спробу. Якщо локальне сховище недоступне, не оновлюйте сторінку до підтвердження відповідей сервером.
6. Завершення тесту спочатку надсилає непідтверджені відповіді. Якщо вчитель уже завершив спробу, її оцінка автоматично не змінюється: локальні дані зберігаються, а кнопка **«Зберегти копію відповідей»** завантажує JSON для ручної перевірки вчителем. Ця копія містить відповіді учня; передавайте її лише своєму вчителю. Автоматичного імпорту таких копій немає.
7. Після завершення результат та правильні відповіді показуються відповідно до налаштувань учителя. Учень бачить використану кількість проходжень. Якщо залишилися дозволені проходження або встановлено «Без обмежень» і сесію не закрито, **«Повторно пройти тест»** створює нову спробу зі збереженим ПІБ. Після вичерпання ліміту кнопка приховується.

Локальна копія допомагає пережити розрив зв’язку, але не замінює резервні копії сервера. Очищення даних браузера або зміна пристрою видаляє/залишає поза доступом локальні чернетки.

## 8. Результати та Аналітика

У фільтрі **«Учні»** виберіть **«Окремі учні поза списком»**, щоб переглянути дітей, яких немає в переданих списках вашого журналу. Його можна поєднати з класом проведення, сесією та пошуком за ім’ям; CSV-експорт зберігає вибраний фільтр. Також є посилання зі «Списків та синхронізації».

Нові ручні входи з того самого браузера пов’язуються зі сталим записом; повторне проходження зберігає його. Учні з різними ID залишаються різними, навіть коли їхні імена однакові. Інший браузер, очищення cookies або інше написання імені можуть створити інший запис. Дозвіл учителя на проходження поза списком залишається обов’язковим для тесту з прив’язаним списком.

Після синхронізації ці діти та їхні оцінки доступні в каталозі окремих учнів журналу без створення навчального класу. Подробиці: [Окремі учні](OUTSIDE_STUDENTS.md).


- **Результати сесії**: перегляд підсумкової таблиці балів та відсотків.
- **Експорт**: завантаження результатів у CSV (Excel) та індивідуальних HTML-звітів для кожного учня.
- **Аналітика складності питань (Item Analysis)**: гістограма розподілу оцінок та відсоток успішності по кожному питанню тесту.

## 9. Типи питань та Смарт-оцінювання

- **`single_choice`**: Одиночний вибір.
- **`multiple_choice`**: Множинний вибір (бали нараховуються за повний збіг чи частково).
- **`true_false`**: Твердження Вірно/Невірно.
- **`short_text`**: Коротка відповідь. Зі **Смарт-оцінюванням (алгоритм Левенштейна)** система вибачає 1-2 опечатки та перестановку слів.
- **`image_choice`**: Вибір потрібного зображення серед кількох варіантів.
- **`matching`**: Встановлення відповідності (пари Ліва -> Права).
- **`sequence`**: Встановлення правильної послідовності.
- **`hotspot`**: Вказівка/виділення інтерактивної області на зображенні.

## 10. Оновлення системи

Адміністраторам доступний розділ **«Оновлення»** у навігаційній панелі (`/teacher/updates`):
1. **Перевірка наявності оновлень**: за кнопкою «Перевірити оновлення» система опитує GitHub API та локальний реєстр релізів `RELEASES.json`.
2. **Детальний список змін (Changelog)**: якщо знайдено нову версію (наприклад, перехід через кілька проміжних випусків), інтерфейс групує зміни по версіях, показуючи підсумковий опис, дати та списки виправлень і нововведень для кожної версії.
3. **Безпечне встановлення**: процес оновлення виконується в 5 ізольованих етапів (перевірка зв'язку, підготовка та пробна збірка в git worktree, резервне копіювання томів даних, фінальне перемикання образу, перевірка здоров'я).
4. **Автоматичний відкат**: у разі виникнення збоїв або невдалої перевірки healthcheck сервіс автоматично повертає попередню версію та стан бази даних. Також доступна кнопка ручного відкату за наявності збереженої резервної копії.



Оновлення системи: пункт «Оновлення» у меню вчителя доступний admin. Якщо admin не створено, оновленнями керує перший учитель, який налаштував сайт. Перед запуском автоматично створюється резервна копія.
