# Перевірка синхронізації класу — SchoolTest 1.6.4

Випуск від 2026-10-14 прибирає загальний список учнів із прив’язок ID та додає підбір відповідностей у потрібному класі. Новий розділ «Окремі учні» входить у вкладки сторінки списків.

## Як працювати вчителю

1. Відкрийте **Списки → Синхронізація**. У розділі «Класи» підтвердьте відповідний місцевий клас або створіть новий. Учні чекають на рішення класу; після підтвердження підбір доступний одразу.
2. Перевірте пари **отриманий ПІБ → місцевий ПІБ**. У списку лише учні цього класу; точні й схожі імена показані першими. Пошук звужує список і зберігає поточний вибір.
3. **Підтвердити точні збіги** прив’язує однозначні пари всього класу за одним підтвердженням. Локальні імена та ID зберігаються. Тезки, кілька претендентів на один ID, різні отримані версії та неточні збіги потребують окремого рішення.
4. Для окремої пари оберіть учня й дані: локальне написання або отримане написання та активність. Для нового учня позначте **Створити нового учня**: прив’язка очищається, використовується отримана версія. Однаковий ПІБ сам по собі нікого не об’єднує.
5. Після підтвердження зміни передаються автоматично за сталими ID. Одночасні зміни з’являються для перевірки. Якщо запис або склад кандидатів змінилися після перегляду, групове підтвердження цілком відхиляється; оновіть сторінку.
6. **Списки → Окремі учні** показує учнів із завершеними спробами поза списком журналу, кількість активних та архівних спроб, до 20 записів і переходи до повного списку. Це не навчальний клас. Сторінка результатів пояснює фільтр, має повернення до вкладки; CSV відповідає активній/архівній вкладці й класу сесії.

## Що перевірено

Усі записи тестів синтетичні. Робочих учнів не зіставляли й реальних результатів не змінювали.

- **122 Python-перевірки сервісу**: API імпорту класів із журналу, вхід учня, права доступу, збереження відповідей, повторні проходження, фільтри й CSV, оновлення, міграції та нові сценарії підтвердження.
- **22 перевірки протоколу обміну**: три незалежні репліки, сталі ID, повтори, відсутній зв’язок, конфлікти, явні прив’язки й збереження локальної історії.
- **Нові HTTP-перевірки**: спочатку клас; кандидати лише його учні; точні та неточні ПІБ; групове підтвердження; тезки; чужий клас; підміна форми; змінений учень або новий тезка після перегляду; транзакційне відхилення застарілих форм; архівний CSV із класом сесії.
- **Docker / Python 3.11 / PostgreSQL 16**: збірка застосунку й шаблонів, обидва драйвери PostgreSQL, HTTP-сценарії, повторний запуск старої схеми та міграція SQLite → PostgreSQL.
- **PostgreSQL-перевірка прив’язок**: два підтверджені учні зберегли ID й історичний результат; явне створення додало рівно одного нового учня; повторна зміна з джерела не створила дубліката.
- **Chromium**: підтвердження класу, пошук, групове підтвердження, створення нового учня, згорнуті готові записи, вкладка окремих учнів, архівний CSV, повернення та перезавантаження вкладки. Екрани 1280×900 і 390×844, без горизонтального виходу сторінки та JavaScript-помилок.
- **JavaScript черги відповідей**: перевірка наявного `student_sync.test.cjs` пройшла.

## Відтворення

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python -m unittest discover -s school_sync/tests
docker build -t schooltest-roster-check:1.6.4 .
RUNTIME_CHECK_IMAGE=schooltest-roster-check:1.6.4 docker compose -p schooltest-roster-review-check -f tests/compose.runtime.yaml up -d --wait app
RUNTIME_CHECK_IMAGE=schooltest-roster-check:1.6.4 docker compose -p schooltest-roster-review-check -f tests/compose.runtime.yaml run --rm checks
docker exec schooltest-roster-review-check-app-1 python /app/tests/roster_review_runtime.py seed
# Запустіть tests/browser_roster_review.cjs у Playwright 1.56.1 у мережі
# schooltest-roster-review-check_default, із доступним іменем app:8000.
docker exec schooltest-roster-review-check-app-1 python /app/tests/roster_review_runtime.py verify
RUNTIME_CHECK_IMAGE=schooltest-roster-check:1.6.4 docker compose -p schooltest-roster-review-check -f tests/compose.runtime.yaml down
```

`seed` запускається один раз у новій тестовій БД. Сценарії PostgreSQL відхиляють робочу БД за адресою, назвою та користувачем. Compose має окремий проєкт і тимчасову БД, без робочих портів та томів.

## Встановлення

Штатне оновлення до 1.6.4 створює перевірену резервну копію та збирає новий образ. API v2 і схема БД залишаються сумісними; наявні класи, ID, відповіді й оцінки не потребують перенесення. Після встановлення перевірте `/healthz`, `/api/version` і відкрийте сторінку списків заново.

Виправлення встановлюється на сайті тестів; змінювати код журналу для цих форм не потрібно. Журнал ініціює передачу списків і отримання оцінок своїми чинними кнопками. Зіставлення реальних неоднозначних учнів залишається дією вчителя.

## Підтверджене встановлення на робочому сервері

Випуск 1.6.4 встановлено штатним оновлювачем із `origin/main`, коміт застосунку `515f90ea04c9`. Оновлювач завершив усі п’ять етапів на 100%; резервна копія — `backups/20261014-203736-ossxp0qa`. Автоматичний відкат не знадобився.

`/healthz` і `/api/version` підтвердили 1.6.4, контейнер застосунку має стан healthy. Перевірено 10 сторінок і запитів із чинними правами вчителя: панель, тести, сесії, списки, загальні й окремі результати, архів, архівний CSV, підключення й опис версії. Лічильники вчителів, тестів, питань, варіантів, сесій, спроб, відповідей, класів та учнів збіглися до й після оновлення. У журналі нового контейнера не виявлено винятків, ERROR або HTTP 500.

Реальні неоднозначні прив’язки не підтверджували: на сайті доступний перевірений підбір, остаточний вибір робить вчитель. Штатний обмін може надалі змінювати свої версії й статистику.
