# SchoolTest 1.8.4 — зображення й маршрути через Funnel

## Налаштування

Для роботи SchoolTest під `/test` на спільному HTTPS-хості додайте
`compose.funnel.yaml` до наявного набору Compose-файлів та задайте в `.env`:

```dotenv
SCHOOLTEST_PUBLIC_HOST=school.example.ts.net
```

Це лише hostname, без `https://`, порту чи `/test`. Публічний маршрут `/test`
має проксувати порт SchoolTest. Кореневий маршрут може належати іншому сайту.
Звичайні локальні адреси працюють без `/test`.

Обгортка активується лише для заданого Host; переписує маршрути HTML/JS,
редиректи, cookie Path та поля `url`/`image_url` JSON. Валідація редактора нормалізує медіашляхи до `/static/...` незалежно від
типу форми, включно з AJAX multipart. Експорт та дані тесту для учня також
нормалізують старі записи з префіксом. Вкладення експорту не переписуються. Текст запитань,
зовнішні URL та вже префіксовані адреси JSON не змінюються.

`SCHOOLTEST_HTTP_CONCURRENCY` обмежує одночасні HTTP-запити; WebSocket не
утримує слот. Типове значення — 20. Пул PostgreSQL — 20 з додатковими 20
з’єднаннями; кількість воркерів потрібно враховувати при зміні цих лімітів.
Очікування блокувань у маршрутах учителя й учня перенесено у фоновий потік,
щоб заблокована транзакція не зупиняла цикл подій.

## Виявлена причина

Серверний модуль переписував HTML, але в JSON обробляв лише `redirect`.
Завантажене зображення повертало `/static/...`, і браузер звертався до
основного сайту замість SchoolTest. Виправлено JSON і зворотне перетворення
під час збереження редактора. Модуль та попередні серверні зміни перенесено
до репозиторію, щоб майбутні оновлення їх зберігали.

## Перевірки 06.11.2026

На публічній адресі перевірено вхід тимчасового вчителя, завантаження PNG,
створення тесту, редагування та збереження зображення запитання й відповіді.
Учень увійшов за скопійованим посиланням, обрав себе зі списку, почав тест,
побачив обидва зображення, надіслав відповідь із серверним підтвердженням
та завершив тест. Результат: 1/1, 12/12; WebSocket моніторингу отримав події.
Наявне зображення повертає однакові байти через локальний і публічний Host.

Тестові дані позначено `funnel_audit_20261106`; їх створення й прибирання окремо дозволив власник. Тимчасового вчителя, тест, сесію, спробу, клас, учня та PNG видалено після перевірки ID й належності.

Використано звичайну перевірку TLS-сертифікатів. Це перевірка перелічених
маршрутів і сценаріїв, а не гарантія всіх можливих поєднань даних і кнопок.

## Автоматичні регресії

Попередній набір 1.8.2: **218/218** на окремій SQLite в контейнері без мережі та робочих томів. Включено 8 перевірок медіатранспорту й обмеження HTTP, захист службових `test.json` з префіксом, збереження прогресу, авторизацію та ліміти спроб.

Під час перенесення чинних серверних змін виявлено блокування одночасного входу/повторної спроби на SQLite. Повні транзакції цих двох маршрутів виконуються в робочому потоці. Перевірка гонки допускає документоване відновлення щойно створеної незапущеної спроби, але вимагає одного ID у редиректах і незмінного ліміту кількості спроб.

Фінальна перевірка AJAX-збереження виявила multipart-випадок, який обгортка URL-encoded форм не охоплювала. У 1.8.4 нормалізацію перенесено до валідації моделей редактора; зайве буферизування форм видалено. Регресія надсилає справжній multipart-запит і перевіряє значення в БД; інша регресія перевіряє незмінність змісту вже призначених питань.

Фінальний код випуску 1.8.4: **221/221** повного набору пройшли у контейнері без мережі на окремій SQLite.

Номер 1.8.3 зайнято паралельно опублікованим виправленням оновлювача (7473176); його код і запис випуску збережено. Multipart-виправлення фіналізовано як 1.8.4, щоб кожна версія мала один запис.
