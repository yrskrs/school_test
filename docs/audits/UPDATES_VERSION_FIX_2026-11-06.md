# SchoolTest 1.8.3 — синхронізація версії та очищення застарілого статусу оновлювача

## Причина проблеми

У розділі «Керування системою → Оновлення системи» (`/teacher/updates`) після завантаження сторінки блок «Поточна встановлена версія» помилково відображав `v1.6.14`, попри те, що в системі було фактично встановлено новішу версію.

### Механізм виникнення:
1. Під час серверного рендерингу шаблону `updates.html` у `#lblCurrentVersion` підставлялося коректне локальне значення `v{{ current_version }}` (з файлу `VERSION` / `app/version.py`).
2. Одразу після завантаження сторінки (`DOMContentLoaded`) JavaScript надсилав запит до `/teacher/updates/api/status`.
3. Маршрут звертався до служби автономного оновлювача (`UPDATER_URL/status`) або читав файл `backups/update_status.json`.
4. Служба оновлювача зберігала в пам’яті та у файлі статус останнього оновлення, виконаного через веб-інтерфейс (2026-10-22 до версії 1.6.14), зі значеннями `state: "success"`, `target_version: "1.6.14"`, `current_version: "1.6.14"`.
5. Обробник `get_update_status()` у бекенді застосунку повертав ці дані без синхронізації з поточною локальною версією запущеного застосунку.
6. Клієнтська функція `renderStatus()` у `updates.html` бачила статус `complete` і безумовно перезаписувала `lblCurrentVersion` значенням `data.current_version || data.target_version` (`v1.6.14`), а також показувала повідомлення про завершення старого оновлення замість спокійного стану системи.

## Внесені виправлення

1. **`app/services/updates.py`**:
   - `get_update_status()` гарантовано встановлює `data['current_version'] = get_current_local_version()`, забезпечуючи відповідність дійсному стану запущеного коду.
   - Якщо статус повідомляє про завершене або перерване завдання (`state != 'running'`), цільова версія якого нижча за поточну версію застосунку (`target_version < local_ver`), статус автоматично скидається до `idle` («Готово до роботи», progress 0, target_version None), запобігаючи маскуванню під активне нещодавнє оновлення.

2. **`scripts/updater_service.py`**:
   - Функція `load_status()` під час запуску й обробники `GET/POST /status` динамічно зчитують актуальну версію репозиторію через `get_current_version()`.
   - Застарілі завершені завдання з цільовою версією нижче поточної автоматично скидаються в стан `idle` і зберігаються у `STATUS_FILE`.

3. **`app/templates/updates.html`**:
   - Додано функцію `updateDisplayedVersion()`, яка звіряє номер версії і ніколи не занижує відображену на сторінці версію через застарілі відповіді фонового статусу.

4. **Тести**:
   - Додано юніт-тести в `tests/test_updates.py`:
     - перевірка примусового перезапису застарілого `current_version` від демона;
     - автоматичне скидання застарілого завершеного завдання старішої версії в стан `idle`.
   - Додано регресійні перевірки в `scripts/test_updates_ui.cjs` та `scripts/test_updater_jobs.py`.

5. **Документація та конфігурація**:
   - Оновлено `CHANGELOG.md`, `RELEASES.json`, `VERSION`, `app/version.py`, `compose.yaml`, `Dockerfile` та `README.md` до версії 1.8.3.
