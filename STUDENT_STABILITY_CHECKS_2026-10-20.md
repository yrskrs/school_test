# SchoolTest 1.6.9 — стабільність учнівського тестування

## Проблеми та базовий план

1. Вирівняти масштаб і тему: незалежні fixed-кнопки мали різні координати й висоту. Тепер на сторінках входу, інструкції та результату вони в одній flex-панелі з однаковою висотою 36 px; на панелях учителя й тесту також узгоджені розміри.
2. Зменшити інструкцію після входу. Прибрано декоративну іконку, зменшено ширину, відступи та статистику; правила сформульовано коротко й відповідно до фактичного надсилання. Перевіряється видимість кнопки початку без прокручування після вибору учня зі списку та звичайного входу.
3. Пояснити збереження та перевірку мережі. Панель розрізняє локальну чернетку, очікування підтвердження та кількість підтверджених відповідей. Ручна перевірка показує процес, успіх або помилку, зокрема всередині офлайн-вікна. Паралельні перевірки не запускаються. Офлайн редагування й переходи блокуються; обидва таймери зупинені. Автоматичні повтори залишаються кожні 3 секунди, також обробляється browser online. Відновлення не скасовує паузу вчителя; після успіху інтервал повторів очищується й для призупиненої спроби.
4. Усунути зависання після трьох попереджень. Діагностика робочого сервісу показала, що сервер уже мав статус `stopped` і три події. Клієнтський код при непідтвердженій чернетці відмовлявся відкривати підсумок; повторне з'єднання намагалося знову зберегти відповідь у вже завершену спробу. Тепер підтверджений кінцевий стан завжди відкриває підсумок. Локальна копія зберігається й доступна для завантаження на сторінці результату. При відсутності підтвердження зупинка повторно перевіряється; є ручна перевірка та завантаження копії замість неактивного вікна. Прибрано блокувальний native alert.
5. Перевірити регресію, офлайн, паузу, втрату підтвердження та розміщення на окремій PostgreSQL. Після перевірок — резервування, Docker, звіряння даних, коміти й GitHub.

Повільні WebSocket-підключення додатково обмежені очікуванням 2 секунди. Монітори отримують повідомлення паралельно; завислий клієнт не утримує надсилання іншим. Відключення старого учнівського WebSocket не видаляє нове підключення після перенесення спроби.

## Що означає резервна копія

Вибір відповіді створює чернетку у браузері цього пристрою. Серверний прогрес також отримує чернетки, але остаточна відповідь надсилається кнопкою «Відповісти» або при завершенні. Після підтвердження сервером інтерфейс збільшує лічильник підтверджених відповідей. Локальне сховище є резервом для обриву зв'язку й перезавантаження сторінки. Воно не означає окрему оцінку й не підмінює серверні резервні копії.

Якщо сервер уже зупинив тест, непідтверджені відповіді не змінюють його оцінку автоматично. На підсумку можна завантажити JSON для вчителя. Локальна копія не стирається лише через те, що спроба перейшла в кінцевий стан.

## Перевірки

- Python: `python -m unittest discover -s tests -p 'test_*.py'` — **142/142**. Зокрема нові сценарії повільного WebSocket і збереження нового підключення після таймауту старого.
- Протокол списків: `python -m unittest discover -s school_sync/tests` — **22/22**.
- JavaScript: `node tests/student_sync.test.cjs` — **26 сценаріїв**, 8 файлів розібрано. Додано кінцевий стан із чернеткою, видимі результати перевірки, відновлення призупиненої спроби та помилку відхиленої відповіді.
- `node tests/monitor_performance.test.cjs`: 20 перепідключень залишають один heartbeat; 50 паралельних оновлень — один HTTP-запит.
- Chromium: `tests/browser_student_stability.cjs` — **7 груп перевірок**: інструкція/вирівнювання; три фактичні виходи з fullscreen; зупинка вчителем із чернеткою; відхилена чернетка + втрачена HTTP-відповідь зупинки + закритий WebSocket; третє порушення офлайн; обидва таймери/редагування/повернення мережі/HTTP 503; пауза вчителя під час відновлення. Перевіряється реальне завантаження локальної копії.
- PostgreSQL окремо перевіряє кінцеві статуси, кількість порушень і збережених відповідей, один запис зупинки на спробу та незачеплену спробу іншого учня.

Сценарії використовують лише `tests/compose.runtime.yaml`, синтетичних учителів і тимчасову PostgreSQL без портів хоста, робочого `.env` або робочих томів. Наповнення й перевірка БД: `tests/student_stability_runtime.py`; режим `reset` видаляє тільки тестові спроби власного синтетичного вчителя. Докази: [reports/student_stability_2026-10-20](reports/student_stability_2026-10-20).

Правила підрахунку порушень, оцінювання, прив'язка учня та API інтеграції не змінені. Схема БД не змінюється. Перевірки браузера виконані в Chromium; Firefox/Safari та довге навантажувальне тестування не проводилися.

Підсумкові браузерні докази: **0 помилок JavaScript і 0 native alert/dialog**. Інструкція повністю вміщується на 1366×768, 1280×720 і 1024×600 при 100%; також без прокручування при 150% на 1366×768 і 1280×720. Верхні координати кнопок однакові (12 px при 100%), висоти — по 36 px.

Повторено попередню регресію: **136 перевірок розміщення** одинадцяти сторінок учителя та учнівських сторінок, введення коду, кількість 200/25 і завершення тесту — успішно. Перевірка областей зображень і обох видів перетягування при 60/80/100/150% — **8 груп**, успішно. Штатний `tests/runtime_postgres_check.py` підтвердив драйвери PostgreSQL, реальний HTTP, повторну доставку подій, кінцевий статус, оновлення старих колонок та міграцію SQLite → PostgreSQL.
